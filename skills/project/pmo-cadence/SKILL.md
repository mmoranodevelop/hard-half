# PMO Cadence

**Program / PMO operating rhythm — one page** — standup → weekly status → SteerCo → phase gates → portfolio: who, when, artefact, decision rights. Default: multi-workstream program or client PMO; same spine for internal transformation office. **Not** the MD's personal week.

Method origin: PMO operating-model cadence + MSP / PRINCE2 governance layers (team → PM → board / SteerCo → programme / portfolio) — nested forums with clear decision rights and artefacts, not more meetings for their own sake.

If they want a PMO / MSP lecture: one paragraph then produce or stop.

## When to use

- "Who meets when, brings what, and decides what?" for a program / PMO
- Cadence is bloated, missing a layer, or decision rights are fuzzy
- Standing up a new program office before kickoff
- Align agile team rhythm to SteerCo / gate calendar without double-reporting

## When not to use

- MD personal week (calendar / energy) — [Weekly Cadence](../../productivity/weekly-cadence/SKILL.md)
- One SteerCo sitting pack (≤3 decisions) — [Steering Pack](../../project/steering-pack/SKILL.md)
- Shop ops KPIs / exceptions — [Operating Review](../../management/operating-review/SKILL.md)
- Roadmap / tranche timeline — [Program Roadmap](../../project/program-roadmap/SKILL.md)
- Board / corp calendar of meetings — [Board Calendar](../../management/board-calendar/SKILL.md)
- One project's internal week narrative — [Weekly Status](../../project/weekly-status/SKILL.md)

## Modes

| Mode | When | Output |
|---|---|---|
| **produce** | Default. Named program / PMO | Cadence page + ASK |
| **redline** | They pasted a meeting zoo | Force who/when/artefact/D; kill status-only forums |
| **refuse** | No program name, or they want the MD calendar | Issues list. Stop |

## Hard rules

1. **Named program / PMO + sponsor.** Not a personal productivity week.
2. **Layers on the page** (use what exists): standup / team sync → weekly status → SteerCo → phase gate → portfolio. Skip empty layers; do not invent ghost forums.
3. **Each forum:** cadence (when), owner, audience, artefact in, decisions out (R/A/C/I or D), duration cap.
4. **Decision rights beat attendance lists.** If nothing is decided there, it is not governance — cut or merge.
5. **Artefact → forum mapping.** Weekly status feeds SteerCo; gate pack feeds go/no-go; do not rebuild the same deck thrice.
6. **One ASK** — stand up / cut / merge / re-time a forum, or assign missing D. Owner, date.
7. **Never invent** calendars, owners, or decision rights. Holes stay holes.
8. **One page.** Rhythm board, not a RACI novel.

## Intake

If **two** of 1–3 are missing after one round: issues list, not a fake calendar.

1. Named program / PMO + sponsor — load-bearing
2. Existing forums (or "greenfield") — load-bearing
3. Who has D on scope / cost / date / risk at which layer — load-bearing
4. Delivery method (agile / waterfall / hybrid) affecting team cadence
5. Gate / tranche dates if known
6. Pain: too many meetings / missing SteerCo / late decisions
7. The ASK this period

## QA (must pass)

1. Named program / PMO + sponsor (or HOLE).
2. ≥3 layers with when / owner / artefact / decision (or explicit skip).
3. Decision-rights block present.
4. One ASK with owner, verb, date.
5. Not weekly-cadence, not a single steering pack, not board-calendar.
6. No invented owners or forums. One page.

If 1, 4, or 6 fail: do not ship.

## Escalate / stop

- They want the MD's personal operating week → [Weekly Cadence](../../productivity/weekly-cadence/SKILL.md).
- Next sitting needs decisions now → [Steering Pack](../../project/steering-pack/SKILL.md); cadence still owns the rhythm.
- No sponsor / no D after one ask → refuse ghost governance.
- Portfolio funding fight → escalate; [Program Roadmap](../../project/program-roadmap/SKILL.md) / portfolio tools own prioritization detail.

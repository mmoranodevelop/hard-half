# project

Client project delivery — charter to close, one job per page.

## Model-invoked

Reachable by you *or* selected automatically by the agent when a task matches.

- [`acceptance-signoff`](acceptance-signoff/SKILL.md) — Use for client UAT / acceptance of named deliverables: tests, evidence, named acceptor, fail path.
- [`assumption-log`](assumption-log/SKILL.md) — Use when load-bearing project assumptions need owners, validate/kill dates, and status — not the mixed RAID page, not a pre-mortem, not a kill-criteria card for one bet.
- [`benefits-realization`](benefits-realization/SKILL.md) — Use when post-go-live (or mid) benefits must be scored vs business-case assumptions with owners and one ASK.
- [`budget-baseline`](budget-baseline/SKILL.md) — Use when locking or reviewing the signed cost baseline: buckets, approved total, as-of, variance drivers vs actuals this period (NOT EAC forecast).
- [`change-control`](change-control/SKILL.md) — Use for one scope, cost, or time change against a signed baseline: baseline vs proposed, impact, approve/defer/reject, ASK the sponsor.
- [`client-ticket`](client-ticket/SKILL.md) — Turn a raw client request into a structured tracker ticket (ClickUp, Jira, Asana, Linear) bound to the list's live custom fields, statuses, and checklists.
- [`contingency-reserve`](contingency-reserve/SKILL.md) — Use when governing the contingency/risk reserve: amount, unlock owner, triggers, remaining balance, draws, one ASK.
- [`critical-path`](critical-path/SKILL.md) — Use when naming this week's critical path + slips + float + one ASK to protect the path.
- [`cutover-plan`](cutover-plan/SKILL.md) — Use for the hour-by-hour cutover of a named go-live: sequence, owners, freeze, rollback trigger.
- [`decision-log`](decision-log/SKILL.md) — Use for a short project/program audit trail of settled decisions: D, date, alternatives killed, revisit trigger; one ASK if stale.
- [`dependency-unblock`](dependency-unblock/SKILL.md) — Use for ONE named dependency (internal/external/vendor): owner, need-by, unblock options, one ASK.
- [`eac-pulse`](eac-pulse/SKILL.md) — Use when Estimate at Complete / Estimate to Complete must be compared to budget and actuals with one ASK.
- [`estimate-confidence`](estimate-confidence/SKILL.md) — Use when a delivery date and/or cost needs a confidence band (P50/P80 or best/likely/worst), named drivers, and one ASK.
- [`go-live-readiness`](go-live-readiness/SKILL.md) — Use for the go / no-go on a named go-live: exit criteria, defects, owners, rollback.
- [`ims-rollup`](ims-rollup/SKILL.md) — Use when rolling up >=2 component schedules into one program IMS view: program milestones, slip deltas, critical cross-links, one ASK.
- [`interdependency-map`](interdependency-map/SKILL.md) — Use when a program has cross-project dependencies that need owners and an unblock ASK — critical cross-links only.
- [`issue-escalate`](issue-escalate/SKILL.md) — Use for ONE named issue: impact, options tried, escalate ladder, one ASK.
- [`kickoff-pack`](kickoff-pack/SKILL.md) — Use for the first session with client and team after the charter is signed: purpose, in/out, RACI pointer, next 2 weeks, ASK to start.
- [`lessons-register`](lessons-register/SKILL.md) — Use when maintaining a living cross-project lessons register: lesson, source project, action, owner, due, status, reuse.
- [`milestone-burn`](milestone-burn/SKILL.md) — Use when milestones need a traffic light plus burn/slip rate and one ASK.
- [`ops-handover`](ops-handover/SKILL.md) — Use when a project must hand to BAU: run owners, runbooks, SLAs, open defects, hypercare exit, one ASK.
- [`phase-gate`](phase-gate/SKILL.md) — Use when a named delivery phase (design/build/UAT/etc.) needs exit criteria go/no-go, holes, and one ASK.
- [`pmo-cadence`](pmo-cadence/SKILL.md) — Use when designing the program/PMO operating rhythm: standup → weekly status → SteerCo → phase gates → portfolio — who, when, artefact, decision rights.
- [`program-roadmap`](program-roadmap/SKILL.md) — Use when a program needs this-quarter waves/tranches, capacity, and the decisions the board must take — one page, one ASK.
- [`project-charter`](project-charter/SKILL.md) — Use when writing the one-page authorisation for one client project: outcome, in/out, sponsor, dates, budget envelope, success tests.
- [`project-close`](project-close/SKILL.md) — Use to close a named project: outcomes vs charter, leftovers, handover, lessons pointer to AAR.
- [`project-health`](project-health/SKILL.md) — Use when scoring RYG health of ONE named project this period: delivery, risk, stakeholder, commercial (or capacity) flags + because + one ASK.
- [`quality-dod`](quality-dod/SKILL.md) — Use when a named deliverable or phase needs Definition of Done / quality gate BEFORE client acceptance: exit criteria, evidence, residual defects, Go/No-Go to present for accept.
- [`raci-delivery`](raci-delivery/SKILL.md) — Use when naming who does the WORK on named deliverables: Responsible, Accountable, Consulted, Informed.
- [`recovery-plan`](recovery-plan/SKILL.md) — Use when a project is red and needs a 14-day recovery pack: stop-doing, critical-path protect, resource, stakeholder message, one ASK.
- [`schedule-crash`](schedule-crash/SKILL.md) — Use when compressing the critical path: crash vs fast-track options with cost/risk, recommended path, one ASK.
- [`scope-baseline`](scope-baseline/SKILL.md) — Use for in/out scope baseline + cost of saying yes to a creep ask.
- [`sponsor-brief`](sponsor-brief/SKILL.md) — Use for a 15-minute LIVE 1:1 with the PROJECT sponsor: agenda spine, 3 facts, 1 decision, landmines, close ASK.
- [`sponsor-status`](sponsor-status/SKILL.md) — Use for the client-facing one-pager this period: on track / at risk / off, exceptions, one ASK.
- [`steering-pack`](steering-pack/SKILL.md) — Use for a steering-committee sitting: up to 3 decisions needed, exceptions, capacity.
- [`vendor-milestone`](vendor-milestone/SKILL.md) — Use at mid-delivery vendor milestone accept/reject: evidence vs SOW, defects, payment gate, one ASK.
- [`vendor-orchestration`](vendor-orchestration/SKILL.md) — Use when one program has multiple vendors (SI / agencies / specialists) and needs who-leads-whom: cross-vendor RACI, named integration owner, interface risks, one ASK.
- [`weekly-status`](weekly-status/SKILL.md) — Use when writing the INTERNAL delivery-team weekly narrative: what happened / what matters / risks that moved / next week / one ASK.

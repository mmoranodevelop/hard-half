# Pyramid Principle

Make thinking easy to grasp: one point at the top, grouped reasons under it, evidence under those.

Default skin is **email**. The same pyramid becomes a Slack thread, a deck, or a 30-second verbal update. It does not become a board paper (use [Executive Board Memo](../../management/executive-board-memo/SKILL.md)) and it does not become a brainstorm.

Public source, not a book dump. Minto's site: ideas are easy to grasp if they are organised as a pyramid under a single point. [barbaraminto.com](https://www.barbaraminto.com/). Reconstruct the operating rules. Do not quote the textbook.

## When to use

- Write, rewrite, or critique an **email** that must be acted on or decided from
- The same argument as a **Slack / Teams / chat** message
- A **verbal update** (standup, hallway, 3 minutes with a principal)
- An **argumentative deck** (recommendation with action titles) — not a board pack
- "Make this clearer / shorter / more executive"

## When not to use

- Board / ELT **decision paper** (that skill)
- Thanks, condolence, congratulations, apology-as-relationship
- Diverge / brainstorm / "what could we do"
- Teaching someone who asked for the journey, not the answer
- A story whose point is earned (case teaching, fundraising narrative)
- Legal filings written by counsel
- A status dump with no point (ask what the point *is*; if none, do not fake a pyramid)

If they want a board paper, say so and route. If they want a carousel, that is a different skill.

## Modes

| Mode | When | Output |
|---|---|---|
| **produce** | Default. New piece | Pyramid + native pack |
| **rewrite** | They pasted a draft | Same facts, new pyramid. Show the governing thought you inferred |
| **critique** | "is this clear?" | Fail the QA list; rewrite the top and any mixed grouping |
| **outline** | They will write it | Governing thought + 2–4 key lines + order named. Stop |

If unclear: **produce** for a blank ask, **rewrite** if they pasted text.

## Pack (mandatory second step)

After you have a pyramid, pick **one** pack. Default **email**.

| Pack | Native unit | First screen |
|---|---|---|
| **email** | One message, one topic | Subject + first two sentences |
| **slack** | Message 1 in a thread | Message 1 is the whole point |
| **deck** | Action-title slides | Title slide = governing thought |
| **verbal** | Spoken, interruptible | First 15–30 seconds |

Same pyramid. Different length, greeting, and chrome. Never paste an email into Slack or a memo onto slides.

## Hard rules

1. **Governing thought is a complete-sentence claim**, not a topic, not a question, not "quick update".
2. **Think bottom-up, present top-down.** Do not make them reenact the analysis.
3. **Vertical:** each point summarises the group below. A parent that only names the category ("three risks") fails. State what the group *implies*.
4. **Horizontal:** ideas in a group are the **same kind**. Either inductive (similar reasons → inference) or deductive (premise → premise → therefore). No mix.
5. **Induction at the key line** unless the answer will surprise them. Deduction is for a paragraph, or for the rare "you asked for X; you actually need Y".
6. **Order is a test:** time (process), structure (parts of a whole, MECE), or rank (importance). If you cannot name it, regroup.
7. **MECE on key lines.** No overlap. If all are true, the governing thought follows. 2–4 lines, usually 3. A fifth is usually two that should merge or a new email.
8. **SCQ is the opening, not the piece.** Situation (agreed) → Complication (what changed) → Question (in *their* mind) → Answer (governing thought). Compress. Skip Situation if they live in it. Never four paragraphs of setup.
9. **One ask.** Named owner, date if action. A second ask is a second message, or a numbered pair you admit is two.
10. **Cut** anything that does not serve a key line that does not serve the governing thought.
11. **Tone is not structure.** Bad news still leads with the point. Soften words, do not bury.
12. **Load a voice overlay** if [Voice Blueprint](../../writing/voice-blueprint/SKILL.md) has one for this channel. Do not invent a "consultant voice".

## Build the pyramid (always, before prose)

Do this on paper (or in the outline) *before* the email.

1. **Ask / decision / point, one sentence.** If they cannot say it, you cannot write it. Ask once.
2. **Who** must act or know, and what they already believe.
3. **Question in their mind** after the complication (SCQ). If you cannot name it, you are broadcasting.
4. **Key lines** that make the governing thought true. Same kind. MECE. Name the order.
5. **Evidence** under each line (one fact, number, or example). Do not put evidence in the parent.
6. **Kill** leftovers. Appendix / later / nowhere.
7. **Title+first-line test:** if they read only the governing thought and the key-line sentences, do they have the argument?

Deductive vs inductive cheat:

| Use induction when | Use a short deduction when |
|---|---|
| Recommendation, weekly update, ask | The answer contradicts what they asked for |
| They already want a decision | They will reject the claim without the chain |
| Email / Slack / verbal | Rare; still put the *action* as soon as the chain allows |

## Pack: email (default)

```
Subject: [governing thought, or ASK: verb + object + date]

[Answer / ask in sentence 1–2. Include the decision and the date if there is one.]

[Optional one-line SCQ if they do not share context.]

[Key line 1 — claim. One supporting fact.]
[Key line 2]
[Key line 3]

[Logistics: owner, date, what you need back, attachments named not dumped.]
```

Rules for this pack:

- Subject is a claim or an ask. Banned: "Quick question", "Update", "Following up", "Touching base", the project name alone.
- First screen is enough to act. If the ask is in paragraph four, you failed.
- **To** = actors. **Cc** = need-to-know. Bcc almost never.
- One topic. If you need a second topic, split.
- Short paragraphs (1–3 sentences) or tight bullets under a claim sentence. Bullets are for key lines, not for a junk drawer.
- Active voice. Named people, named dates.
- No "hope this email finds you well", "just circling back", "per my last", "as discussed" without the point.
- Attachments: say what they are and what to look at. Do not send a deck as a substitute for the email.
- Reply: **their question first**, then anything extra. Quote-thread only what you are answering.
- Length: if it needs a table of contents, it is a memo. Offer the memo skill or cut.

Italian/English: match the thread. Lei vs tu belongs to the voice overlay, not this skill.

## Pack: slack (and similar chat)

- Message 1 = governing thought + ask. @ the owner.
- Thread = key lines as bullets. Evidence on request or one line each.
- No greeting novel. No "hi team," then context, then the point at 18:00.
- Do not pyramid "thanks" / "on it" / emoji.
- If the channel is noisy, the first line must stand in the unread list.
- Links after the ask, not instead of it.

## Pack: deck (argumentative slides)

- Slide 1 (title or exec summary): governing thought as an **action title** (complete sentence).
- Slide 2 (agenda): the 2–4 key lines, also claims, not "Background / Analysis / Next steps".
- One section per key line. Each slide headline is the so-what of that slide.
- Evidence on the body; source on the slide. Fake precision is a fail.
- Summary: restates governing thought + key lines. Then one ask slide if a decision is needed.
- Appendix: the work you cut.
- Title+first-line test on the slide titles alone.
- **Not** a board pack. If directors must minute a resolution, stop and use the board-memo skill; you may later *adapt* the same governing thought into slides.

## Pack: verbal

- First 15–30 seconds: answer + ask. Then stop.
- "Three reasons:" (or two). If they nod, do not deliver the appendix.
- If they challenge a line, go **down one level**. Do not restart from Situation.
- Do not narrate method ("I pulled SAP, then I…").
- Have the number for each key line in your pocket. Say it only if asked or if it is the proof.
- End with the ask and the date, then shut up.

## Rewrite mode

Infer their governing thought (state it). If the draft has two, split or pick with them. Rebuild key lines. Keep their facts; throw away their order. Show a short diff of *structure* (old buried ask → new first sentence), not a redline of every comma.

## Critique mode

Run QA. Name failed checks. Rewrite the governing thought and any mixed grouping. Do not add "more colour".

## Intake

Ask only what is missing. Refuse to draft an action email with no ask and no point.

1. **Pack** (email default)
2. **Who** acts / who reads
3. **Governing thought** (or the decision / ask)
4. **What they already know** (so SCQ can be short)
5. **Proof** for each key line (numbers they actually have — do not invent)
6. **Deadline and owner**
7. **Voice overlay** if one exists
8. **Language**

## Output shape

Lead with the pyramid, then the native piece.

```markdown
# Pack: email | slack | deck | verbal

Governing thought: …
Question in their mind: …
Key lines (kind: reasons | steps | parts; order: time | structure | rank):
1. …
2. …
3. …

## The piece
[native email / slack / spoken script / slide titles + so-whats]

## Cut to appendix / not sent
- …
```

For email, the piece includes Subject, To/Cc suggestion if it matters, body. For deck, action titles for every slide in order, plus a one-line visual note only if needed. For verbal, a script they can say aloud in under a minute, then optional backup bullets.

## QA (must pass)

1. Governing thought is a disagreeable complete sentence.
2. First screen / first 15 seconds contains it and the ask.
3. 2–4 key lines, same kind, MECE.
4. If all key lines are true, the parent follows.
5. Order named, or a short deduction you chose on purpose.
6. No leftover that does not serve a key line.
7. Pack is native.
8. One ask, owner, date if action.
9. Active voice; no throat-clearing.
10. Title+first-line test (verbal: they could repeat the ask).

If 1, 3, or 4 fail: do not ship. Rebuild the pyramid.

## Escalate / stop

- No point and no ask after one question → stop. Offer bullets of facts, not a fake recommendation.
- They want the buried-bad-news sandwich → refuse the bury; offer a direct first sentence with a human tone.
- They want a clone of a McKinsey deck look → give action titles and logic, not a stolen template.
- Numbers you do not have → leave a hole, do not invent.
- Board paper → other skill.
- Voice they asked to match → load the blueprint; this skill still owns structure.

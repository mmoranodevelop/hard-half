# Value Eng

**Value / ROI one-pager (or one simple sheet)** the AE defends: 3–4 consensus goals, baseline from *this* customer, driver table, assumptions table, output labelled illustrative, one sourced analogue. Customer inputs visually distinct (blue in kit, or labelled **INPUT**). Default: venture / mid-market deal in late discovery. Chrome from [Document Kit](../../documents/document-kit/SKILL.md) (MM optional or consulting-neutral).

Method origin: Trailhead Vision & Value Maps (3–4 consensus goals; impact from **the customer’s budget and current metrics**; industry data only as fallback) + Nucleus Research (vendor) 3-year TCO shape (software + hardware + personnel + professional services + training; ROI + payback) + Force Management Value Framework proof points (training vendor). FSC datasheet 188% is Nucleus / Sequoia Financial Group — an analogue, not this buyer’s output cell.

If they want an ROI lecture: one paragraph, then produce or stop.

## When to use

- AE must defend a number in the room this week
- Consensus goals exist; customer will give volume / cost / time inputs
- A simple model (one sheet), not a capital pack

## When not to use

- Board capital case (NPV, IRR, stage-gate) — [Business Case](../../strategy/business-case/SKILL.md)
- Contribution of one more unit — [Unit Economics](../../strategy/unit-economics/SKILL.md)
- IB/PwC three-statement grid — [Finance Workbook](../../documents/finance-workbook/SKILL.md)
- Proof callout on a datasheet — [Sales Datasheet](../../documents/sales-datasheet/SKILL.md)
- Named-customer FILE — [Sales Proposal](../../documents/sales-proposal/SKILL.md) (this page is an **annex**)
- Permissioned story as the artifact — [Proof Story](../../comms/proof-story/SKILL.md)
- McKinsey leave-behind — [Consulting Deck](../../documents/consulting-deck/SKILL.md)

## Modes

| Mode | When | Output |
|---|---|---|
| **produce** | Default. Customer inputs exist | One-pager + assumptions |
| **redline** | "50% productivity" pasted with no INPUT | Kill invented %; emit inputs checklist |
| **refuse** | No customer inputs; they want this buyer’s cell = Nucleus 188%; capital case | Issues list + route |

## Hard rules

1. **Customer inputs required.** Volume, cost base, time — marked **INPUT** (kit: accent/blue for inputs, not for output). No inputs → emit an **inputs checklist**, not a fake ROI. Clock of the pack.
2. **3–4 consensus goals** among multiple leaders, not one person’s hobby metric (Trailhead Value Map).
3. **Driver table:** each row = driver, formula, INPUT, analogue/benchmark (sourced, labelled), output. Nucleus (vendor) 3-year TCO is the *shape* of defensibility, not a 40-tab model.
4. **Assumptions table.** Explicit, dated, owner. "If hours saved are not backfilled, cash does not appear."
5. **Output is illustrative / based on inputs above.** ROI, payback, or annual benefit. Never paste another customer’s ROI (Nucleus/Sequoia 188%; FedEx customer-story +2,000%) into *this* output cell — cite as analogue only.
6. **HOLE any cell** that would require inventing a savings rate. Industry survey may fill a **benchmark** cell only if labelled benchmark, not this customer’s result.
7. **Gartner / Forrester: reprint or silence.** No fake MQ as the value proof. No "No. 1 / winner."
8. **One page** or one simple sheet. WACC / NPV scenarios / Board pack → business-case.
9. **Kit, not clone.** Never Cloud blue, Salesforce Sans, Lightning. Input colour is a token, not Salesforce blue.

## Intake

If **customer name** and **at least two live INPUTs** (volume, cost, or time from *this* org) are both missing after one round: **inputs checklist**, not a fake page.

1. Customer + 3–4 consensus goals (load-bearing)
2. Current metrics and cost base — **INPUT** (load-bearing with 1)
3. Required capabilities vs today
4. Driver list they will defend (hours, headcount, error cost, cycle time)
5. Analogue they may cite (named + source) — or none
6. Term (usually 3-year TCO shape) + who presents
7. Kit (default consulting-neutral); mark INPUT vs analogue vs output

## Output shape

Fill `assets/artifact.md`. Spine:

```
VALUE / ROI  |  [Customer]  |  [date]  |  illustrative — based on inputs
GOALS (3–4 consensus)
BASELINE (INPUT): [volume / cost / time]
DRIVERS: driver | formula | INPUT | analogue (source) | output
ASSUMPTIONS (dated, owner) — backfill rule stated
OUTPUT: ROI / payback / annual benefit  [model, not a promise]
ANALOGUE: [named + source] — not this cell
ASK: [EB] confirms INPUTs by [date]; AE presents
Holes: [ ]
```

## QA (must pass)

1. Customer named. INPUTs exist and are labelled. No vendor-invented %.
2. Assumptions table present; backfill / cash-appearance stated.
3. Output labelled illustrative. Analogue cited, not pasted as this buyer’s ROI.
4. Every number is INPUT, sourced analogue, or `[HOLE]`.
5. Not a business-case, unit-econ, or finance workbook. One page / one sheet.
6. ASK: confirm inputs + present — owner + date.
7. No fake MQ. No Cloud-blue clone (input colour ≠ Salesforce Cloud blue).

If 1, 3, 4, or 5 fail: do not ship.

## Escalate / stop

- "Assume 50% productivity" with no INPUT and no source → refuse; checklist.
- They want Nucleus 188% in the output cell → refuse; analogue line only.
- NPV / WACC / Board cheque → [Business Case](../../strategy/business-case/SKILL.md).

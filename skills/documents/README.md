# documents

Client-facing and internal document artifacts.

## Model-invoked

Reachable by you *or* selected automatically by the agent when a task matches.

- [`battle-card`](battle-card/SKILL.md) — Use when shipping a one-page competitive leave-behind for a NAMED rival: landmines, traps, landmine questions, proof.
- [`consulting-deck`](consulting-deck/SKILL.md) — Use when producing a strategy-consultant leave-behind .pptx: Minto pyramid/SCQ, action titles as takeaway sentences, one exhibit per slide, exec summary first, appendix out of the room.
- [`document-kit`](document-kit/SKILL.md) — Use when setting colours, type, grid, lockup, and light/dark tokens for business files (deck, Excel, PRD, paper).
- [`finance-workbook`](finance-workbook/SKILL.md) — Use when making a real .xlsx: IB three-statement MODEL or ISA/PCAOB WORKING-PAPER / flux — never mixed.
- [`prd-spec`](prd-spec/SKILL.md) — Use when builders need a spec: one named problem, RFC 2119 MUST with test and owner, non-goals, alternatives, privacy, rollout/kill.
- [`research-paper`](research-paper/SKILL.md) — Use when producing an IMRAD (or venue) manuscript: claim, evidence, limitation, methods that replicate, labelled confirmatory vs exploratory.
- [`sales-datasheet`](sales-datasheet/SKILL.md) — Use when shipping a 1–2 page product/offer sheet: outcome H1, who, Three Reasons, use cases, sourced proof, how-it-works caption, features grid, one CTA.
- [`sales-proposal`](sales-proposal/SKILL.md) — Use when producing a customer-named proposal FILE: cover, this-customer situation, recommended solution, commercial, assumptions, next step.
- [`solution-brief`](solution-brief/SKILL.md) — Use when shipping a 4–8 page industry or persona solution brief: Challenger order, Required Capabilities before the offer, permissioned proof, architecture, one CTA.
- [`trust-pack`](trust-pack/SKILL.md) — Use when producing a security/compliance/architecture one-pager a CISO can keep: SPARC-shaped, named audits with scope/date/exclusions or HOLE.
- [`value-eng`](value-eng/SKILL.md) — Use when producing a quantified value/ROI one-pager or simple model the AE can defend: assumptions table, customer inputs required (labelled INPUT).

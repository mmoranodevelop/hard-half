# Proof Story

**Proof Story — One Customer / One Metric / Permission** — one page sendable to a prospect: customer (named or anonymized — labelled), situation/pain in one line, one M1 metric with time window, permission status (written / named public / anonymized / internal-only / expired), the sentence the Champion or EB can repeat in one breath, match-to-this-deal. Default: venture (peer logo matters — still no name without permission). Same spine for F500 (anonymized is allowed if labelled).

Method origin: MEDDICC (training vendor) M1 existing-customer outcomes + public permission/relevance rules (Forrester relationship framing; Peerbound vendor approval). https://meddicc.com/what-is-meddpicc/metrics

If they want a case-study / proof lecture: one paragraph then produce or stop.

## When to use

- This week’s demo, EB 30 minutes, proposal cover, or Champion brief needs one proof
- A logo wall or superlative is what we currently send
- Permission status is unknown and someone wants to name the customer anyway
- One objection or metric on this deal matches one existing customer

## When not to use

- The request *to* the customer — [Reference Ask](../../commercial/reference-ask/SKILL.md)
- Post go-live tracking toward M3 — [Value Realization](../../accounts/value-realization/SKILL.md)
- Why we won or lost — [Win Loss](../../strategy/win-loss/SKILL.md)
- Quarterly account recap — [QBR](../../management/qbr/SKILL.md)
- The proposal cover that *cites* this proof — [Proposal Narrative](../../comms/proposal-narrative/SKILL.md)

## Modes

| Mode | When | Output |
|---|---|---|
| **produce** | Default. One metric + permission status + relevance writable | One-breath story + ASK |
| **redline** | They pasted a logo wall, PDF case study, or unpermissioned quote | Force one metric + permission label; kill the wall |
| **refuse** | Two of metric / permission / relevance / repeatable sentence missing; or they want the ask-script to the customer | Issues list. Stop |

## Hard rules

1. Clock is **this week, one story**. One customer. One metric. Not a library.
2. MEDDICC (training vendor): **M1** = outcomes already delivered for existing customers (Economic / Efficiency / Risk). M3 post-go-live flows back into M1 via [Value Realization](../../accounts/value-realization/SKILL.md) — not here.
3. **Permission status is load-bearing.** Peerbound (vendor): always get **written approval** before public name, logo, or quote; anonymize if needed; archive churned; refresh 12–18 months. If permission unknown → stop; route [Reference Ask](../../commercial/reference-ask/SKILL.md). Do not write the ask-script here.
4. Number + window. “They loved us” is not a proof-story.
5. Relevance to *this* buyer (industry, size, use case, or objection). Peerbound (vendor, 6,500+ sales-rep queries): stories/case studies/similar lists **66.6%**; “someone in this industry” **28.3%**; “how customers succeed” **23.3%**.
6. Repeatable in one breath. If it takes a PDF, it is not this skill. RAIN Group (training vendor): “persuaded me we would achieve results” is a top separator; ROI case alone is not enough — risk and process sit beside the number.
7. Forrester (Amy Bills): asking is a relationship, not a favor — that operating advice lives in [Reference Ask](../../commercial/reference-ask/SKILL.md). Here we only *use* a proof that already has permission.
8. Do not invent metrics, names, or permission. Holes stay holes.

## Intake

If **two** of 1–4 are missing after one round: issues list, not a fake story.

1. One metric the customer achieved (number + window) — load-bearing
2. Permission status (written / named public / anonymized / internal-only / expired) — load-bearing
3. Relevance to this buyer (industry / size / use case / objection) — load-bearing
4. Repeatable sentence (one breath) — load-bearing
5. Customer named or anonymized (labelled)
6. Situation/pain in one line
7. Where it will be used this week (demo / EB / cover / Champion brief)

```
NOT THIS PAGE: the ask to the customer → reference-ask; post go-live tracking → value-realization; win/loss interview → win-loss; QBR recap → qbr

ASK: [owner] uses this sentence on [date] in [meeting]. Permission re-checked: Y/N

```

## QA (must pass)

1. One number + window — not a superlative.
2. Permission status on the page; unknown → do not ship.
3. Relevance to this deal stated.
4. One-breath sentence.
5. ASK + owner + date.
6. Not a reference ask, value recap, win-loss, or logo wall.
7. One page.

If 1, 2, or 5 fail: do not ship.

## Escalate / stop

- Name / logo / quote without recorded permission → refuse.
- Permission unknown → issues list; [Reference Ask](../../commercial/reference-ask/SKILL.md).
- They want the ask-script to the customer → refuse this skill; route.
- They want a methodology class → one paragraph then produce or stop.

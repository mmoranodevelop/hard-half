# Operating Review

**One-page exception review** (weekly default) plus exception cards. Monthly skin only when the question is reallocation, not last week's operation. Default: venture weekly. Same spine for F500.

Method origin: Amazon WBR public + lean visual management — exceptions, not tours.

If they want to explain a WBR / teach OGSM: one paragraph then produce or stop.

## When to use

- This week's (or month's) pack must be exception-based
- A status tour must become a one-pager an MD can fly
- Reds exist but have no owner, date, or next action

## When not to use

- One named decision in a room — [Decision Meeting](../../management/decision-meeting/SKILL.md)
- The MD's personal calendar spine — [Weekly Cadence](../../productivity/weekly-cadence/SKILL.md)
- Board / ELT paper — [Executive Board Memo](../../management/executive-board-memo/SKILL.md)
- Go/Kill a bet — [Portfolio Stage-Gate](../../management/portfolio-stage-gate/SKILL.md)
- Living RAID dump — [RAID Register](../../management/raid-register/SKILL.md)
- First authorisation — [Program Charter](../../management/program-charter/SKILL.md)
- OKR design — [OKR Cascade](../../strategy/okr-cascade/SKILL.md)

## Modes

| Mode | When | Output |
|---|---|---|
| **produce** | Default | Filled one-pager + cards |
| **redline** | They pasted a status pack | Same facts, exception-first; list what you killed |
| **refuse** | Missing load-bearing inputs, or they want a tour / board pack labelled MOR | Issues list. Stop |

Pasted slides → **redline**. Every workstream on stage → **refuse**.

## Hard rules

1. **Exceptions, not tours.** Page 1 only if it can change a decision this period.
2. **Split metrics:** controllable input / output / context.
3. **Colour with named thresholds.** Grey (no data) = red for the instrument.
4. **Each yellow/red:** owner, cause-or-unknown, action (not "monitor"), date.
5. **Pull last period's follow-ups onto the page.**
6. **One ASK the chair can close (Type 2 only).** Type 1 → park; route to [Decision Meeting](../../management/decision-meeting/SKILL.md).
7. **Weekly = customer/operation + inputs. Monthly = P&L, capacity, persistent reds, resource moves.** Do not run a monthly P&L every week.
8. **Do not invent numbers or root-cause.** "Unknown" is allowed.

## Intake

If **two** of 1–4 are missing after one round: issues list, not a fake page.

1. Cadence — weekly (default, venture) or monthly (reallocation / P&L)
2. Scope — P&L, program, plant. Chair. What is *out* — load-bearing
3. Plan of record — numbers we said we would hit. If none: say so — load-bearing
4. Metrics they actually have — name, owner, input vs output, yellow/red threshold — load-bearing
5. This period's exceptions — off-standard, or "we have not looked"
6. Last review's open follow-ups

Cannot name one metric that would change a decision this period → refuse the review.

## QA (must pass)

1. ASK (or explicit "none this sitting").
2. Named chair + period date.
3. Page 1 has a number where a number is required (actual, plan, or "unknown").
4. A red/yellow has owner + date + action that is not "monitor".
5. Not a workstream tour or a board-pack narrative.
6. Weekly pack is not running monthly P&L questions (or the reverse).
7. No invented numbers or invented root-cause.
8. One page.

If 1, 4, 5, or 7 fail: do not ship.

## Escalate / stop

- No metrics and no way to get them → issues list.
- They want every workstream, two minutes → refuse the tour.
- Board pack labelled "MOR" → [Executive Board Memo](../../management/executive-board-memo/SKILL.md).
- Safety / quality / cyber red saved for the monthly → escalate now.
- Type 1 in the weekly room → [Decision Meeting](../../management/decision-meeting/SKILL.md).
- Punishing "I don't know" → refuse to script a fake cause.

# Issue Tree

**Diagnosis pack (one page):** governing question, MECE tree, starred branches, workplan with owners and dates. An MD can run the 30-minute meeting from it. Default: venture / program.

Method origin: Minto grouping test + public case-interview craft — one root question, MECE branches, 80/20 work. Not a Firm manual.

If they want to be taught MECE: one paragraph then produce or stop.

## When to use

- "Why is X down / broken / late?" and the cause is not known
- "How do we attack this?" once the cause is known (solution tree)
- Scoping a program: what must be true, what we will not work
- The room keeps debating solutions and has not agreed the problem

## When not to use

- Write the recommendation / email / deck — [Pyramid Principle](../../writing/pyramid-principle/SKILL.md)
- Board / ELT decision paper — [Executive Board Memo](../../management/executive-board-memo/SKILL.md)
- Capital choice with cash flows — [Business Case](../../strategy/business-case/SKILL.md)
- Named-rival "what do we do" — [Competitive Teardown](../../strategy/competitive-teardown/SKILL.md)
- After the program is scoped into Os — [OKR Cascade](../../strategy/okr-cascade/SKILL.md)
- The governing question itself may be a decoy (fix shipped, nobody's Monday changed) — `ghost-problem`
- SWOT / 3Cs paste, or a brainstorm with no question — name the question first, or stop

## Modes

| Mode | When | Output |
|---|---|---|
| **produce** | Default | Filled diagnosis pack (why-tree unless they already know the driver) |
| **redline** | They pasted a tree / "framework" | Fail QA; redraw first split; no decoration |
| **refuse** | No question, or they want the tree as the memo | Issues list. Stop |

Never mix why-branches and how-branches on the same level.

## Hard rules

1. **Governing question is a complete, bounded sentence.** "Profitability" is a topic — refuse.
2. **First split: 2–4 branches, one logic** (algebra / process / one segmentation axis). Mixing "revenue" and "operations" as siblings fails.
3. **MECE at every level.** Overlap test + gap test written on the page.
4. **Leaves are tests**, not labels. "Did list price or mix drive the gap?" not "price."
5. **Hypothesis = complete sentence + first test + kill number or kill fact.** Star 2–3 branches. Do not visit every node.
6. **Workplan = starred leaves only;** analysis, source, owner, date. Cheapest decisive test first.
7. **Numbers you do not have stay [HOLE].** Custom tree — no SWOT, no generic 3Cs paste.
8. **This pack is not the recommendation.** When diagnosis lands, stop and write a pyramid.

## Intake

If **two** of 1–3 are blank after one pass: issues list, not a fake tree.

1. Governing question (what, how much, by when, vs what) — load-bearing
2. Decision / owner / date this tree serves — load-bearing
3. Diagnose or solve — load-bearing
4. Already known (do not re-tree settled facts)
5. Data you actually have / scope in-out
6. Working hypothesis if they have one

## QA (must pass)

1. ASK + owner + date present.
2. Governing question is a disagreeable complete sentence, not a topic.
3. Mode named; why and how not mixed at one level.
4. Level-1 is 2–4, one logic, MECE check filled.
5. Every leaf is testable and traces to the trunk.
6. Hypothesis has a first test and a kill number/fact (or [HOLE]).
7. Workplan covers starred leaves only; owners and dates.
8. One page. No framework paste. No invented numbers. No "therefore we should" pyramid.

If 1, 2, 4, or 6 fail: do not ship.

## Escalate / stop

- They want the tree as the memo → [Pyramid Principle](../../writing/pyramid-principle/SKILL.md) after diagnosis.
- They want a board paper now → [Executive Board Memo](../../management/executive-board-memo/SKILL.md).
- They want NPV of options → [Business Case](../../strategy/business-case/SKILL.md).
- They will not name a governing question → refuse.

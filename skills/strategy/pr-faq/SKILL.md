# PR/FAQ

**Future-dated Press Release + FAQ** — one-page PR as if it launched, then external FAQ then internal FAQ. Customer is the hero. Status: iterate / kill / ready for the money test. Default: venture product or program.

Method origin: Amazon Working Backwards public (Bryar/Carr write-ups + Bezos letters: customer first, resist proxies).

If they want a Working Backwards lecture: one paragraph then produce or stop.

## When to use

- New product, service, policy, or program still unbuilt
- "Should we even build this?" before headcount and code
- Skills-forward idea that needs a customer
- Kill-or-commit on slideware that has lived for months

## When not to use

- Launch comms for something that already exists — real comms, not this skill
- Capital math — [Business Case](../../strategy/business-case/SKILL.md) after this customer test
- Job unclear — [Jobs to Be Done](../../strategy/jobs-to-be-done/SKILL.md) first
- Competitor-back with no customer — [Competitive Teardown](../../strategy/competitive-teardown/SKILL.md)
- Board paper — [Executive Board Memo](../../management/executive-board-memo/SKILL.md)
- Live incident statement — [Crisis Holding](../../writing/crisis-holding/SKILL.md)
- OKRs for a funded program — [OKR Cascade](../../strategy/okr-cascade/SKILL.md)

## Modes

| Mode | When | Output |
|---|---|---|
| **produce** | Default | Future-dated PR + external FAQ + internal FAQ + ASK |
| **redline** | They pasted a blog, PRD, or deck | Customer-back; vanity killed |
| **refuse** | Two load-bearing facts missing, or a guaranteed-win FAQ | Issues list. Stop |

Honest kill is a valid produce.

## Hard rules

1. **Customer is the hero.** Named segment, not "everyone". Not the company, not the model.
2. **Date in the future.** City + date on the PR. A PR dated today for an unbuilt product is a lie.
3. **PR ≤ 1 page.** Heading, subhead (who + benefit), problem, solution vs what they use today, company quote, hypothetical customer quote, how to start.
4. **FAQ: external first, then internal.** Internal is truth-seeking: why it dies, economics or HOLE, what must be true.
5. **Meaningfully better / faster / cheaper** than the current solution (including do-nothing).
6. **No vanity / proxies.** Banned: brand love, AI-powered, synergy, NPS-as-customer. Use time saved, cost avoided, job completed.
7. **Skills-forward is a fail** — could not have been written from the current roadmap alone.
8. **Do not invent TAM or WTP.** Holes stay holes. Two-sided marketplace → two PRs, one shared internal FAQ.

## Intake

If **two** of 1–3 are missing after one round: issues list, not a fake PR.

1. Customer segment (not "users") — load-bearing
2. Problem they already pay time or money to cope with — load-bearing
3. Current solution (incumbent, workaround, or nothing) — load-bearing
4. Future launch date (even if rough)
5. Kill tests (what would make this not worth building)
6. Constraints you must not hide
7. Decision this meeting is for (iterate / kill / fund discovery)

## QA (must pass)

1. ASK + owner + date. Future city+date on the PR.
2. Customer is a segment; they are the hero.
3. Problem from their POV; solution addresses that problem.
4. Current substitutes named; better/faster/cheaper is specific.
5. PR ≤ 1 page; FAQ external then internal.
6. No vanity metrics.
7. Internal FAQ includes why it dies, economics or HOLE, what must be true.
8. Skills-forward test fails (this is not the current roadmap).
9. Status is honest.

If 2, 3, 6, or 8 fail: do not ship.

## Escalate / stop

- They want a PR/FAQ that cannot fail → refuse; that is a brochure.
- Technology with no customer job after one ask → refuse.
- They want the cheque modelled → [Business Case](../../strategy/business-case/SKILL.md).
- Copy of an incumbent → kill.
